# Markdown 语法指南

> 面向本项目的写作手册。所有"站里能/不能"的判断都基于实际渲染器实测，不是照抄通用文档。

---

## 1. 先搞清楚：你面对的是两个渲染器

你写的同一份 `.md`，会被两套完全不同的解析器渲染：

| | 渲染器 | 用在哪 |
| --- | --- | --- |
| 站点 | `react-markdown` v10 + `remark-gfm` v4 | 线上文章页 `/article/xxx` |
| 编辑器 | Obsidian 自带解析器 | 你本地写稿时的预览 |

**两者能力不一样**，所以"Obsidian 里好看"不代表"线上好看"。下面这张表是关键：

| 语法 | 站点 | Obsidian |
| --- | --- | --- |
| 标题、强调、列表、链接、引用、代码 | 支持 | 支持 |
| 表格、删除线、任务列表、自动链接 | 支持 | 支持 |
| 脚注 `[^1]` | 支持（但样式朴素） | 支持 |
| 裸 HTML 标签 `<kbd>` | **不支持**，会显示成字面文本 | 部分支持 |
| 双链 `[[某页]]` | **不支持**，原样显示 | 支持 |
| 嵌入 `![[图片.png]]` | **不支持** | 支持 |
| Callout `> [!note]` | **不支持**，退化成普通引用块 | 支持 |
| frontmatter | 读取 `title` / `desc` | 显示为属性面板 |

<http://localhost:3000> 之类的裸 URL 在两种环境下都能自动变成链接。

结论：**只用两边都支持的交集**，就能保证所见即所得。

## 2. 基础语法

### 2.1 标题

```markdown
# 一级标题
## 二级标题
### 三级标题
#### 四级标题
```

站里 **h1–h3 有专门样式**（衬线字体、逐级缩小），h4–h6 走默认样式。

⚠️ 文章页顶部已经有一个 `<h1>`（就是你的 `title`），所以**正文请从 `##` 开始**，不要再用 `#`。

### 2.2 段落与换行

段落之间用**一个空行**分隔。行内换行在 Markdown 里会被合并成同一段——想强制换行，行尾加两个空格，或者干脆另起一段。

### 2.3 强调

```markdown
*斜体*
**粗体**
***粗斜体***
~~删除线~~
```

站里 `strong` 的字重被设为 500（比默认的 700 轻），这是设计上的选择，不是 bug。

### 2.4 列表

```markdown
- 无序项
- 另一项
  - 缩进两格就是子项

1. 有序项
2. 第二项
```

站里只给 `ul` / `ol` / `li` 写了基础样式，**没有自定义序号或符号**，就是普通的圆点和数字。

### 2.5 链接

```markdown
[显示的文字](https://example.com)
[站内跳转](/clouds)
```

站里链接是紫色下划线（`#6f5b95`）。站内路径用 `/article/zoudiu` 这种相对根路径。

### 2.6 图片

```markdown
![图片描述](/images/xxx.jpg)
```

- 图片文件放在 `public/images/` 下，路径写 `/images/文件名`
- 站里**没有给图片写样式**：不会自动居中也限制不了宽度，建议提前把图裁到合适尺寸
- Obsidian 的 `![[附件.png]]` 写法在线上不生效，必须用标准 Markdown 语法

### 2.7 引用

```markdown
> 这是一段引用。
> 可以写多行。
```

站里样式：左侧 2px 琥珀色竖线（`#e8d5c4`）+ 灰字（`#6e6e6e`）。很适合放"一句留给自己的话"。

### 2.8 行内代码与代码块

行内用单反引号包住，比如 `npm run dev`。

代码块要用三个反引号围起来，并在开头标注语言：

```markdown
（这里写三个反引号，紧跟语言名，比如 js，然后换行写代码，最后用三个反引号收尾）
```

⚠️ 站里**只给 `code` 元素写了样式，没给 `pre` 写**——也就是说代码块只有浅灰底，没有内边距和横向滚动条。**长代码行会溢出容器**，写代码时请手动折行或缩短。

### 2.9 分隔线

三个短横线单独成行：

```markdown
---
```

⚠️ **正文里慎用**。文件开头的 `---` 是 frontmatter 分隔符，正文中间出现的 `---` 才被当作分隔线；但如果你在文件最前面忘写 frontmatter，第一处 `---` 可能被误判。站里也没给 `hr` 写样式，就是浏览器默认的一条细线，视觉上比较突兀。

## 3. GFM 扩展语法

### 3.1 表格

```markdown
| 左对齐 | 居中 | 右对齐 |
| :--- | :---: | ---: |
| A | B | C |
```

站里有完整表格样式（1px 边框、内边距、字号略小）。表格前后**必须各留一个空行**，否则不会渲染。

### 3.2 任务列表

```markdown
- [x] 已完成的事
- [ ] 还没做的事
```

站里会渲染成**不可点击的勾选框**（`disabled`），适合写清单。注意：它不是真的待办功能，读者点不了。

### 3.3 脚注

```markdown
这里有个说法[^1]。

[^1]: 补充说明写在页面底部。
```

站里会生成上标数字 + 页面底部的脚注区。但**没有专门样式**，会以一个 `sr-only` 的 "Footnotes" 标题开头，观感一般，正式文章里少用。

### 3.4 自动链接

裸写 URL 会自动变成链接（GFM 特性）：

```markdown
访问 https://example.com 就能看到
```

但 markdownlint 会报 `MD034` 错误，规范写法是用尖括号包起来：`<https://example.com>`。

## 4. 本项目的 frontmatter

只有 `content/articles/` 下的文件才会发布，且**必须**以 frontmatter 开头：

```markdown
---
title: 走丢
desc: 走丢本身，也是一种抵达
---
```

| 字段 | 必填 | 作用 |
| --- | --- | --- |
| `title` | 是 | 目录卡片标题、详情页大标题、浏览器标签 |
| `desc` | 是 | 目录卡片摘要、详情页副标题、SEO 描述 |
| `date` | 是 | 发布日期 `'YYYY-MM-DD'`，决定在单行道上的位置 |
| `cover` | 否 | 封面图路径或外链，不填则用程序化生成的封面 |
| `tags` | 否 | 内容分类数组，如 `[迷惘, 深夜]` |

- 漏 `title` → 用文件名当标题
- 漏 `desc` → 摘要为空
- frontmatter **不会**显示在正文里（会被解析掉）
- 在 `content/` 根目录写的笔记不会发布，可以随便当草稿用

## 5. 站里不支持的东西（写之前先看这节）

### 5.1 裸 HTML —— 会显示成文本

```markdown
<span style="color:red">红色</span>
```

线上会**原样输出这串字符**，不会渲染成红色文字。实测输出是转义后的 `&lt;span...&gt;`。

原因：渲染器没启用 `rehype-raw`。所以别指望用 HTML 做居中、改颜色、加锚点。

### 5.2 双链与嵌入

`[[某页]]`、`![[图片.png]]` 在 Obsidian 里好用，线上就是纯文本。**要发出去的文章，链接一律用标准 Markdown 语法。**

### 5.3 Callout

```markdown
> [!note] 提示
> 内容
```

线上只会渲染成普通引用块，而且 `[!note] 提示` 这几个字会**原样显示**出来，很难看。

### 5.4 其他

- 数学公式（`$...$`）：没有引入 KaTeX，不会渲染
- Mermaid 图：不会渲染
- 目录（TOC）：没有插件，需要手写锚点

## 6. 样式现状速查

| 元素 | 站里有没有专门样式 |
| --- | --- |
| `p` `h1` `h2` `h3` | 有 |
| `h4`–`h6` | 无（浏览器默认） |
| `ul` `ol` `li` | 有 |
| `blockquote` | 有（琥珀色竖线） |
| `code`（行内） | 有（浅灰底） |
| `pre`（代码块） | **无** |
| `a` | 有（紫色下划线） |
| `strong` | 有（500 字重） |
| `table` `th` `td` | 有 |
| `img` `hr` `del` | 无 |
| 任务列表勾选框 | 浏览器默认 |
| 脚注 | 无 |

## 7. 提交前跑一次 lint

```powershell
npm run lint:md
```

配置在 `.markdownlint.json`，已经关掉了几条容易误伤中文的规则（行长度 `MD013`、重复标题 `MD024`、行内 HTML `MD033` 等）。

仍然会检查的常见项：

| 规则 | 含义 |
| --- | --- |
| `MD022` | 标题前后要有空行 |
| `MD031` | 代码块前后要有空行 |
| `MD032` | 列表前后要有空行 |
| `MD040` | 代码块要标语言（写 `text` 也算） |
| `MD034` | 不要裸写 URL |
| `MD047` | 文件结尾要有换行 |

## 8. 最小可用模板

```markdown
---
title: 标题写这里
desc: 一句话摘要，会显示在目录卡片上
---

开头这段是正文，不加标题也可以。

## 第一个小标题

正文段落。想强调就 **加粗**，想留白就另起一段。

> 想放一句单独的话，就用引用。

- 列表项一
- 列表项二
```

把它存成 `content/articles/你的-slug.md`，刷新 `npm run dev` 就能看到效果。
