## 0. 一句话结论

> **源文件继续保持 UTF-8，只给编译命令加一个参数 `-fexec-charset=GBK`，中文就正常了。**

不用改系统设置、不用改代码、不用把文件另存成别的编码。

---

## 1. 你遇到的是不是这个现象？

代码里明明写的是：

```cpp
std::cout << "你好，世界！" << std::endl;
```

运行后终端里却显示成：

```text
浣犲ソ锛屼笘鐣岋紒
```

或者一堆 `��`、`锟斤拷`、问号、方块。**编译没有报错，程序也确实运行了，只是中文显示不对**——这就是典型的“编码不匹配”，不是你的代码写错了。

另一个间接信号：如果你在统计“一个汉字占几个字节”，会发现是 **3 个字节**，而有的教材/实验课预期是 **2 个字节**。这同样是本篇要解释的问题。

---

## 2. 为什么会乱码（小白版解释）

计算机里存文字用的是“编码”。同一句中文，用不同编码保存，得到的字节完全不同：

| 文字 | UTF-8 编码（国际通用） | GBK 编码（中文 Windows 常用） |
|---|---|---|
| 你 | `E4 BD A0`（3 字节） | `C4 E3`（2 字节） |
| 好 | `E5 A5 BD`（3 字节） | `BA C3`（2 字节） |

你的程序和终端之间有两段“翻译”，任何一段对不上就会乱码：

```text
① 你的源文件 .cpp          →  保存为 UTF-8
        │  g++ 编译
        ▼
② exe 里的中文字符串        →  默认也是 UTF-8（一个汉字 3 字节）
        │  程序运行时输出
        ▼
③ Windows 终端/控制台       →  默认按 GBK（代码页 936）显示 → 乱码！
```

打个比方：exe 里写的是“拼音”，终端却按“五笔”去读，读出来自然是乱码。

**你可以自己验证：**

1. 在 VS Code 里按 `` Ctrl+` `` 打开终端，输入 `chcp` 回车 → 会看到 `936`（即 GBK）；
2. 打开 VS Code 里任意一个 `.cpp`，看右下角 → 一般显示 `UTF-8`。

两边一致就不会乱码；现在两边不一致，所以要动其中一边。**最省事的做法是让 exe 里的字节变成 GBK**，也就是加编译参数 `-fexec-charset=GBK`。

## 3. 动手解决（跟着做，约 5 分钟）

### 3.0 先确认环境

- 已安装 **VS Code**；
- 已安装 **C/C++ 扩展**（点左侧“扩展”图标，搜索 `C/C++`，选 Microsoft 官方的那个安装）；
- 已安装 **MinGW（g++）**。验证：打开终端（`` Ctrl+` ``），输入：

  ```text
  g++ --version
  ```

  能看到版本号（例如 `g++ ... 16.2.0`）就说明装好了。

> 本教程默认你的 MinGW 已经加进系统 PATH（在终端里输入 `g++ --version` 能看到版本号即可）。如果还没加 PATH，3.3 里给了改用“完整路径”的备用写法。

### 3.1 用「打开文件夹」打开项目（这一步最容易错！）

- VS Code 菜单：**文件 → 打开文件夹**（快捷键 `Ctrl+K` 再 `Ctrl+O`）；
- 选择**存放 .cpp 文件的文件夹**。

**为什么强调这一步？** VS Code 的工程配置都放在项目根目录的 `.vscode` 文件夹里，而 **只有“打开文件夹”时，`.vscode` 才会被读取**。如果你只是双击打开了一个 `.cpp` 文件，配置全部不生效——很多人“照着教程改了却没用”，原因就在这里。

判断自己是不是“打开了文件夹”：

- 左侧资源管理器显示的是**文件夹树**（能看到多个文件），不是空白的；
- 窗口标题栏显示的是文件夹名，而不是单个文件名。

### 3.2 新建 `.vscode` 文件夹

在 VS Code 左侧资源管理器的空白处（或者项目根目录上）**右键 → 新建文件夹**，输入：

```text
.vscode
```

> 小提示：名字最前面的英文句点是必须的；它就是个普通文件夹，只是名字以点开头，在 Windows 文件资源管理器里不太显眼，所以**用 VS Code 的资源管理器新建最方便**。

### 3.3 新建 `tasks.json` 并粘贴内容

1. 右键刚建好的 `.vscode` 文件夹 → **新建文件** → 输入文件名 `tasks.json`；
2. 打开本教程配套的 `01-tasks.json`，把里面**全部内容**复制过去；
3. `Ctrl+S` 保存；
4. （可选）**如果 g++ 不在 PATH 里**：把 `tasks.json` 里的 `"command": "g++"` 改成完整路径，比如 `"command": "C:\\mingw64\\bin\\g++.exe"`：
   - 在终端里执行 `where.exe g++` 可以查到 g++ 的真实位置；
   - **注意**：JSON 里反斜杠要写两个，例如 `C:\mingw64\bin\g++.exe` 要写成 `C:\\mingw64\\bin\\g++.exe`（只写一个会报 JSON 语法错误）。

### 3.4 重新编译并运行

改完配置后**必须重新编译**（旧的 exe 不会自己更新）：

- 按 `Ctrl+Shift+B` 编译当前文件；
- 或者点编辑器右上角的 **▶**（运行 C/C++ 文件），会先编译再运行（第二篇会细讲）。

编译成功后，exe 就“带 GBK 了”，中文输出恢复正常。

## 4. 配置文件逐项说明

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "type": "cppbuild",
      "label": "编译当前C++文件 (g++)",
      "command": "g++",
      "args": [
        "-fdiagnostics-color=always",
        "-g",
        "-std=c++17",
        "-fexec-charset=GBK",
        "${file}",
        "-o",
        "${fileDirname}\\${fileBasenameNoExtension}.exe"
      ],
      "options": { "cwd": "${fileDirname}" },
      "problemMatcher": ["$gcc"],
      "group": { "kind": "build", "isDefault": true },
      "detail": "编译当前 C++ 文件；中文字符串按 GBK 存进 exe，解决中文乱码"
    }
  ]
}
```

| 字段 | 含义 |
|---|---|
| `version` | 任务配置版本，固定写 `2.0.0` |
| `tasks` | 任务列表，可以放多个任务 |
| `type` | **必须是 `cppbuild`**：C/C++ 扩展只认这种类型的任务，点 ▶ 时才会用它编译 |
| `label` | 任务名字，自己起；第二篇的 `launch.json` 会用它 |
| `command` | 编译器：默认写 `g++`（在 PATH 里查找）；不在 PATH 时改成完整路径 |
| `args` | 编译参数，**`-fexec-charset=GBK` 就是解决乱码的关键** |
| `options.cwd` | 在源文件所在文件夹执行编译 |
| `problemMatcher` | 把编译错误显示到“问题”面板（`$gcc` 是 GCC 格式） |
| `group.isDefault` | 设为默认构建任务，`Ctrl+Shift+B` 直接跑它 |
| `detail` | 鼠标悬停时显示的说明，随意写 |

参数里的几个变量（VS Code 会自动替换）：

| 变量 | 含义 | 示例 |
|---|---|---|
| `${file}` | 当前打开的文件 | `D:\cpp\hello.cpp` |
| `${fileDirname}` | 当前文件所在文件夹 | `D:\cpp` |
| `${fileBasenameNoExtension}` | 不带扩展名的文件名 | `hello` |

所以 `-o ${fileDirname}\${fileBasenameNoExtension}.exe` 的意思就是：在源文件旁边生成一个同名的 `.exe`。

## 5. 验证：写个小程序试试

新建 `hello.cpp`：

```cpp
#include <iostream>

int main() {
    std::cout << "你好，世界！" << std::endl;
    return 0;
}
```

打开这个文件，按 `Ctrl+Shift+B` 编译，然后运行：

```text
.\hello.exe
```

- ✅ 正确：显示 `你好，世界！`
- ❌ 如果还是乱码：说明这次编译没带参数（见下面 FAQ 第 1 条）
- 对照实验：把 `tasks.json` 里 `"-fexec-charset=GBK"` 这行删掉再编译一次，就会恢复成乱码

## 6. 常见问题（FAQ）

**Q1：按教程改了，为什么还是乱码？**
按顺序检查：

1. **有没有重新编译？** 旧的 exe 不会自动变，删掉 exe 或重新按 `Ctrl+Shift+B`；
2. 终端里实际执行的 `g++` 命令**有没有带 `-fexec-charset=GBK`**；
3. 你是不是**没有“打开文件夹”**（见 3.1），导致 `.vscode/tasks.json` 根本没被读取；
4. 运行时看的是不是 VS Code 的 **“调试控制台”**——它是 UTF-8 的，GBK 程序输出到那里反而会乱（见 Q4）。

**Q2：编译报错 `converting to execution character set: Illegal byte sequence`？**
说明你的 `.cpp` 被另存成了 **GBK 编码**。修复方法：
在 VS Code 里打开该文件 → 看右下角编码（可能显示 GBK/GB2312）→ 点击它 → **通过编码重新打开** → 选 `UTF-8` → 再点一次 → **通过编码保存** → 选 `UTF-8`。
记住：**源文件永远保持 UTF-8，GBK 只放在编译参数里。**

**Q3：那我直接把 `.cpp` 文件存成 GBK 不就行了？**
不推荐。原因：VS Code 默认 UTF-8，git、其他工具、跨平台都会乱；而且 g++ 默认按 UTF-8 读源码，遇到 GBK 字节会直接**编译报错**（见 Q2）。我们只需要让“编译出来的 exe”用 GBK 就够了。

**Q4：为什么在“调试控制台”里看输出还是乱码？**
VS Code 的“调试控制台”按 UTF-8 解码，而我们的程序输出是 GBK，所以它会乱。**别用调试控制台看程序输出**：用底部终端，或者让程序跑在独立窗口里（见第二篇）。

**Q5：在终端里先执行 `chcp 65001` 也能解决？**
可以，但不推荐：每个新窗口都要设置一次；而且中文会变成 3 字节（和实验课的预期不符）；一些老控制台字体也不支持。还是加编译参数一劳永逸。

**Q6：每次都要手动敲编译命令吗？**
不用。配置好本篇的 `tasks.json` 后，`Ctrl+Shift+B` 就是“编译当前文件”。如果想让 **Ctrl+F5 一键“编译+运行”**，看第二篇。

## 7. 小结

> **乱码 = exe 里的字节编码 ≠ 终端控制台的代码页。**
> **解决：源文件保持 UTF-8，编译命令加 `-fexec-charset=GBK`。**
